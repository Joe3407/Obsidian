## 📘Lec 1

- **Java:**
	- **Technology:** 
		- **Java Virtual Machine (JVM):** 
			- It's the runtime machine that executes Java bytecode stored in `.class` files, which are produced by compiling `.java` source files 
			- It provides the layer that allows the same bytecode to run on different operating systems/platforms through different JVM implementations
		- **Java Runtime Environment (JRE):**
			- It provides JVM, Java libraries, other runtime components
			- It gives the environment necessary to run a Java program 
		- **Java Development Kit (JDK):**
			- It provides JRE, Development tools such as `javac`(which is the compiler), debugger, and other tools 
		- **Relationship:**
			- JDK = JRE + Development Tools
			- JRE = JVM + Java Libraries + Other Runtime Components
	- **Properties:**
		- **Object-Oriented:** It supports concepts such as classes, objects, inheritance, polymorphism, encapsulation, and abstraction
		- **Interpreted:** Java is both compiled and interpreted, It's compiled when it compiles the `.java` file to `.class` file, and It's interpreted when JVM executes the bytecode 
		- **Portable:** Java bytecode is platform-independent and can run on different operating systems through platform-specific JVM implementations
		- **Secure & Robust:** It restricts direct memory manipulation unlike C/C++, which reduces certain memory-related errors and makes programs safer and more robust
		- **Multi-threaded:** Java supports multiple threads of execution within the same program, allowing different tasks to execute concurrently
		- **Garbage Collected:** It automatically reclaims memory from objects that are no longer reachable
		- **No support for multiple inheritance:** No child has multiple parents 
	- **Notes:** 
		- `.java`(source code) $\to$ `.class`(bytecode, compiled) $\to$ JVM (runs, interpret)
		- Bytecode is the same no matter how the OS changes, but the JVM that runs this bytecode is different according to different OS 
- **Object Oriented Programming:**
	- **Terminologies:**
		- Data, Fields, Attribute
		- Method, Function, Procedure 
	- **Principles:** 
		- **Encapsulation:** Exposes only necessary data
		- **Abstraction:** Hide complexity by hiding unnecessary detail from the user
		- **Inheritance:** Allows creating a hierarchy of related classes (Code reusability)
		- **Polymorphism:** The same concept/interface can be used with different forms or behaviors depending on the situation (Overloading, Overriding)

## 📘Lec 2

- **Java Syntax:**
	- **Similar to C++:**
		- `if-else`
		- `switch`
		- `for`, `while`, `do-while`
		- `for each` 
		- `break`, `continue` 
	- **Difference:**
		-                                                   C++                                Java
		- Output:                                     `cout<<`                         `System.out.print()`, `System.out.println()`$\to$ leaves a line 
		- Boolean:                                   `bool`                             `boolean`
		- String:                                       `string`                         `String`
		- String size:                               `s.size()`                    `s.length()`
		- Array declaration:                 `int arr[4]`                `int[] arr = new int[n]`, `int[] arr = new int[]{1,3,6}` 
	- **Class:**
		- **Semi colon:** In C++ there is a semi colon after the class, but in Java there is no semi colon 
		- **Access modifiers:** In Java each attribute and method have its own access modifier before it, and the default is package-private, while C++ have access modifier sections, and the default of it is private
	- **Note:**
		- The `new` in Java is similar to that in C++, meaning it allocates dynamic memory in the heap, but the huge difference is that from Java properties it's **Garbage Collector**, which means unlike C++ it doesn't need the `delete[] arr` it deletes it automatically 
		- **Float:** 
			- C++: In C++ the decimal value is double by default, so when doing `float x = 1.5` it automatically allows the conversion of double to float, it might loose precision while doing so. Another way of writing it is `float x = 1.5f` or `float x = 1.5F`, the only difference is that there is no conversion step from double to float
			- Java: In Java the decimal value is also double by default, but when doing `float x = 1.5`, this action is refused, because it doesn't allow to convert double to float to avoid loosing precision, so it must be written either `float x = 1.5f` or `float x = 1.5F` 
- **Unified Modeling Language (UML):**
	- **Meaning:** It's a standard visual language used to represent a software system's structure and relationships
	- **Uses:**
		- Helps plan and understand a system before implementing
		- It's language independent meaning same diagram applies for different languages
	- **Class diagram:** 
		- Represented by a rectangle having 3 parts: Class name, Attributes, Methods 
		- $+ \to$ public, $-\to$ private, # $\to$ protected
	- **Relation:**
		- **Inheritance:** It means that a class is a type of this parent, and is drawn by an arrow head line pointing to parent, e.g. Dog $\to$ Animal 
		- **Association:** It means that a class is not the parent but shares some roles with it, and is drawn by a solid line, e.g. Student $-$ Course 
- **Packages:**
	- **Meaning:** A container for related classes used to organize code, improve readability and maintainability, and avoid naming conflicts between classes in different packages
	- **Purpose:** Organizes classes and avoids naming conflicts
	- **Naming:** Package names are usually written in lowercase and can contain multiple levels separated by dots
	- **Declaration:** Use `package` at the beginning of the source file
- **Access Modifiers:** 
	- `private`: Accessible within the same class only
	- `public`: Accessible from anywhere
	- None (package-private): Accessible within the same package, it's used when we don't use any modifier 
	- `protected`: Accessible within the same package and subclasses
	- `static`: Belongs to the class, not to a specific object
	- `final` (Attribute): Can be assigned only once, gives compilation error when trying to change the value 
	- `final` (method): Cannot be overridden
	- `final` (class): Cannot be inherited from
	- `extends`: Inherits from another class
	- `super`: Refers to the parent class; can call its constructor or methods
	- `this`: Refers to the current object

## 📘Lec 4

- **Class Reusability:**
	- **Composition:** Making an object of a class inside another class 
	- **Inheritance:** Extend a class with another class 
- **Inheritance:**
	- **Subclass Constructor:**
		- It calls the parent constructor by default if the parent has a default constructor, but if the parent has parameterized constructor then compile error occurs 
		- We can call the constructor of the parent using `super()`, at the start of the child constructor
	- **Note:**
		- It can only have one parent, meaning it can't extend from multiple parents 
		- `final` prevents class inheritance, e.g. `public final class person{}` 
- **Method Overriding:**
	- **Overview:**
		- Access modifier for an overriding method can be same or more, meaning if parent is `protected`, then the child can have `protected` or `public` 
		- `final` doesn't allow overriding, e.g. `public final void display(){}` 
		- Both the child and parent class must have same signature, meaning they must have same name, parameters and same return type 
	- **Overloading Vs Overriding:**
		- Overloading is between methods in the same class, while Overriding is between methods in parent and child class 
		- Overloading method has same name but different parameter number & type also different return type, while overloading only differs in the body 
- **Abstract:**
	- **Class:**
		- **Overview:**
			- Abstract class provides basic implementation that has to be extended to make it complete 
			- Must be Inherited 
			- Can never be instantiated, as it doesn't have any concrete functionality by itself 
		- **E.g:**
			- `public abstract class person{}` 
	- **Method:**
		- **Overview:**
			- It's declared in parent but has no body, needs extend to be complete 
			- If a class has atleast one abstract method, then the class must be abstract 
		- **E.g:**
			- `public abstract void clear();` 
	- **Upcasting:**
		- **Overview:**
			- Since we can't create an object of an abstract class `Vehical v = new Vehical();` is an error so we can use upcasting
			- `Vehical v = new Truck();` this works as `Truck` is part of `Vehical`, but the other way around gives error 
		- **Types:**
			- **Reference type:** Determines which methods and attributes you can access, meaning the ones inside parent class,  `Vehical` is reference type 
			- **Actual object type:** Determines which overridden method implementation executes at runtime, and can't access normal methods, `Truck` is actual object type 
- **Polymorphism:**
	- It contains the Overriding & Overloading, Upcasting & Downcasting, which is explained above
	- **Downcasting:**
		- We can workaround and do it by casting, e.g. `Person p = new Student();`, then `Student s;`, we can cast it and say `s=(Student)p;` 
		- This works but could lead to alot of runtime errors such as runtime exceptions, which occures when `p` is't upcasted and has a `Person` type
	- **`instanceof` Operator:**
		- A child class is `instanceof` child & parent 
		- A parent is only `instanceof` parent 
		- An upcasted class parent is `instanceof` parent & child
